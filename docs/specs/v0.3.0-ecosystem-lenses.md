# v0.3.0 — k3s, Rancher/Fleet, VictoriaMetrics

Status: accepted · Supersedes nothing · Depends on the lens mechanism shipped in
v0.2.0 (`docs/lenses.md`).

## The finding that shaped this release

Twenty-nine proposals were generated from source-verified research across five
areas and then adversarially rated with **cut as the default verdict**. Nine of
them proposed a new lens-schema mechanism. **Seven of those nine were cut**, each
because the pack that justified it was itself cut, or because the capability
already shipped.

The conclusion is the spec: **the lens schema as it stands in v0.2.0 already
expresses every pack in this release.** v0.3.0 is six YAML files, one one-line
bug fix, and documentation. There is no framework work.

## Scope

### In

| # | Item | Mechanism | Ecosystem |
|---|------|-----------|-----------|
| 1 | Lens kinds in the sidebar count sweep | Go — one-line omission | *all packs* |
| 2 | `k3s-helm.yaml` — HelmChart, HelmChartConfig | pure YAML | k3s |
| 3 | `k3s-upgrade.yaml` — system-upgrade-controller Plans | pure YAML | k3s |
| 4 | `fleet.yaml` — GitRepo, Bundle, BundleDeployment | pure YAML | Rancher |
| 5 | `rancher.yaml` — management Clusters, ClusterRepos | pure YAML | Rancher |
| 6 | `victoriametrics.yaml` — VMAgent, VMAlert, VMRule, VMServiceScrape | pure YAML | VictoriaMetrics |
| 7 | VM demo fixture (one headline kind) | fixture | VictoriaMetrics |
| 8 | Composite/filter JSONPath documentation | docs | — |

Item 1 is listed first because it is the one that makes the other seven legible:
`internal/k8s/counts.go` ranges `builtinKinds` when deciding which kinds to
count, so **every lens kind shows a blank sidebar badge until you open it** — you
cannot tell "Fleet is not installed here" from "nothing is broken". `rows.go`
already registers interest in lens kinds; only the sweep drops them.
`countKindUnsafe` resolves through `gvrFor` and a `Limit:1` LIST reading
`GetRemainingItemCount()`, so it touches neither a lister nor a compiled
JSONPath — the `*jsonpath.JSONPath` render-goroutine confinement invariant is
untouched by this fix.

### Out, and why

- **cert-manager + `format: until`** — the highest-value single column found
  (EXPIRES, sorted, where today there is no answer short of a shell loop). Cut
  from v0.3.0 only because it is the one remaining Go change and cert-manager is
  not one of the three ecosystems this release is about. First item in v0.5.0.
- **Flux, Gateway API** — both rated above several items shipping here, both pure
  YAML, both outside the requested scope. v0.5.0 alongside cert-manager.
- **Severity glyphs** (colour-blind safety) — under-costed on review: a leading
  rune shifts every graded cell's width and must cover `statusColors` too, or
  tables render half-glyphed. Its own change, not a rider.
- **Context export (`ctrl+y`)** — needs a redaction path (Secret `.data`,
  `last-applied-configuration`) built first. No clipboard: `atotto/clipboard`
  shells out to binaries absent on headless boxes and OSC 52 truncates below a
  realistic payload. It writes a file and toasts the absolute path, or it does
  not ship.
- **VM cardinality view, vmalert rules view, sparkline cells** — a
  `Column.Format` that needs a reachable VictoriaMetrics endpoint breaks the
  premise that a pack never talks to a cluster.
- **Etcd snapshot inventory (`k3s.yaml`)** — permanently empty on sqlite-backed
  k3s, which is most k3s installs.
- **Rancher `settings`, k3s `Addons`, three of VM's seven kinds** — tables you
  read once and never again. A row in the Resources pane is not free.
- **Free-text patch modals** ("bump the chart version") — that belongs in the git
  repo holding the HelmChart, not in a TUI prompt.

## Constraints (unchanged, non-negotiable)

- **Zero new Go modules.** Every pack here is data.
- No I/O on the render path. `*jsonpath.JSONPath` stays confined to the render
  goroutine.
- Discovery-gated: `requires` gates a pack on group/version **and** resource, all
  kinds, not any. A pack is invisible on a cluster that does not run its operator.
- `just check` passes. Tests sit beside their source. UI verified against a real
  frame via `just shot`, not by reading view code.

## Verification gate — no pack merges on an unverified path

A wrong JSONPath renders an empty column forever and reads as a k10s bug, not as
a missing field. Ten claims reached the backlog unconfirmed. **Each must be read
at its upstream source before the pack that depends on it is written**; a claim
that cannot be confirmed is dropped from its pack, not shipped hopefully.

| # | Claim | Lands in | Verify at |
|---|---|---|---|
| U3 | Fleet `nonReadyResources[].name` is `<ns>/<name>` and the list is capped | `fleet.yaml` | rancher/fleet apis |
| U4 | Cross-namespace label edges resolve only where the target informer covers the namespace | `fleet.yaml` bundledeployment→cluster | `lensedges.go` + a demo-backend test |
| U5 | `helmcharts.helm.cattle.io/chart` label and `.status.jobName` | `k3s-helm.yaml` edge | rancher/helm-controller at tag |
| U6 | `upgrade.cattle.io/plan`, `upgrade.cattle.io/node` label keys | `k3s-upgrade.yaml` edges | rancher/system-upgrade-controller |
| U10 | VM operator core kinds still served at `v1beta1` | `victoriametrics.yaml` requires | VictoriaMetrics/operator api/ |

The four remaining unverified claims (U1, U2, U8, U9) belong to packs and
mechanisms deferred above and are not this release's problem.

## Acceptance

1. `just check` green; `just test-race` reports zero races; `just test-perf`
   passes with the lens row builder inside the guard (it currently has no lens
   coverage at all — add it).
2. Every new pack parses, and one test per pack asserts its kinds compile and its
   columns produce the expected headers.
3. Every pack is invisible on a cluster whose discovery does not serve it — one
   gate test per pack.
4. Sidebar badges count lens kinds: a test that a lens kind appears in the sweep
   output.
5. Demo backend renders the VM kind on `k10s-demo-prod`, verified with
   `just shot`, not by reading the view.
6. `docs/lenses.md` documents the composite/filter JSONPath form
   (`.status.conditions[?(@.type=="Ready")].status`), which already works and is
   the form every pack here needs.

## The daily loops this collapses

**"Traefik's HelmChart is stuck."** Today: `kubectl get helmchart -o yaml`, read
`.status.jobName`, `kubectl get job <name>`, `kubectl get pod -l job-name=<name>`,
`kubectl logs` — five commands, two of which exist only to carry a name to the
next one. After: `:helmcharts`, the FAILED column is already sorted to the top,
`R` lists the install Job by name through the `.status.jobName` field edge,
`enter`, `l`. Four keystrokes.

**"Did the k3s roll finish?"** `:plans` puts the in-flight Plan first, `R` reaches
the upgrade Job through `upgrade.cattle.io/plan`, `R` again reaches the Node
through `upgrade.cattle.io/node`. Three keystrokes, no label selectors typed.

**"Which bundle failed on which cluster?"** `:bundles` sorted worst-first, the
non-ready resource names in the row, `R` to the BundleDeployment and on to the
Cluster. Today that is the Rancher UI in a browser.
