**k3s, Rancher and VictoriaMetrics are in the sidebar now** — HelmCharts and
their install Jobs, upgrade Plans mid-roll, Fleet GitRepos and the bundle that
failed on one cluster, Rancher's opaque `c-m-xxxxx` clusters with their real
names, VMAgents worst-first. Five operators, five YAML files, and one Go line.

## No new mechanism

Twenty-nine proposals came out of a source-verified sweep of these three
ecosystems, then went through an adversarial pass whose default verdict was
*cut*. Nine of them wanted a new lens-schema feature. **Seven of those nine were
cut** — each justified by a pack that was itself cut, or by a capability the v0.2
schema already had.

So this release adds no mechanism. The lens schema shipped in v0.2.0 expresses
all five packs unchanged. What it adds is the one-line fix that makes them
legible.

## Sidebar badges count lens kinds

`internal/k8s/counts.go` decided what to count by ranging `builtinKinds`, so
**every lens kind's badge stayed blank until you opened it**. That is the
difference between "Fleet is not installed on this cluster" and "Fleet is
installed and nothing is broken" — two answers that matter, rendered
identically. The count sweep now ranges lens kinds too.

It reaches them the same way it always reached builtins: `gvrFor` plus a
`Limit:1` LIST reading `GetRemainingItemCount()`. No lister, no compiled
JSONPath — the `*jsonpath.JSONPath` confinement that keeps the row builder
race-free is untouched, and the comment recording *why* now says so, because the
old comment's reasoning ("the sweep never holds a lens key") stopped being true
in this very commit.

## The packs

| Pack | Kinds | The question it answers |
|---|---|---|
| `k3s-helm` | HelmCharts, HelmChartConfigs | why the packaged chart is stuck |
| `k3s-upgrade` | Plans | did the roll finish, and on which node |
| `fleet` | GitRepos, Bundles, BundleDeployments | which bundle failed on which cluster |
| `rancher` | Clusters, ClusterRepos | which cluster is `c-m-lx4kd` |
| `victoriametrics` | VMAgents, VMAlerts, VMRules, VMServiceScrapes | which scrape config is failed |

**"Traefik's HelmChart is stuck."** Today that is `kubectl get helmchart -o
yaml`, read `.status.jobName`, `kubectl get job <name>`, `kubectl get pod -l
job-name=<name>`, `kubectl logs` — five commands, two of which exist only to
carry a name into the next one. Now: `:hc`, the failing row is already at the
top, `R` lists the install Job **by the name the controller recorded**, `enter`,
`l`. The edge reads `.status.jobName` rather than rebuilding
`helm-install-<name>`, because that name flips to `helm-delete-<name>` the
moment a deletion timestamp is set.

**"Did the k3s roll finish?"** `:plan` puts the in-flight Plan first, `R` reaches
the upgrade Job through `upgrade.cattle.io/plan`, `R` again reaches the Node
through `upgrade.cattle.io/node`. Three keystrokes, no label selectors typed.

## What was deliberately left out, and why

Most of this release's work was deciding what not to ship.

**Fleet's force-resync.** `.spec.forceSyncGeneration` is real, and forcing a sync
means writing current+1 — a templated value. k10s renders templated patch leaves
as strings, so the patch would send `"3"` into an `int64` and the API server
would reject it. A button that always fails is worse than no button.

**Pause on a Fleet Bundle.** This one *works* and is then silently undone: the
git job runs `fleet apply` on every sync and replaces the whole Bundle spec, so
the next commit restores `paused: false` with no event and no message. The
operator believes the deployment is frozen while Fleet is applying again. Pause
the GitRepo instead — that one sticks.

**An acknowledgement on Rancher's index refresh.** `.status.downloadTime` is the
right field to watch, but the ack for a non-`annotate` verb is a *presence*
check, and that field is already set on every repo that has ever downloaded an
index. The spinner would clear instantly whether the index was re-pulled or the
catalog controller is wedged — which is the one distinction an ack exists to
make. The write is confirmed; pretending the controller handled it is not.

**`delete` on Rancher Clusters and Fleet GitRepos.** The builtin delete is a
plain danger modal: `D`, `Enter`. Deleting a management Cluster deprovisions a
downstream cluster; deleting a GitRepo garbage-collects every resource it
deployed across every target. Two keystrokes is the wrong price. Those stay in
`kubectl`, where the blast radius is at least typed out.

**Columns that are the same on every row.** A chart-repo URL renders as
`https://…` at 140 columns; Fleet registers every Rancher cluster into
`fleet-default`, so a truncated `<namespace>/<cluster>` cuts off exactly the
cluster name you opened the table to read. `REPO`, `JOB` and a second `MESSAGE`
were cut so `VERSION`, `TARGET NS` and `WORST-CLUSTER` keep the width. Each of
those was found by rendering a real frame, not by reading YAML.

Also out: etcd snapshot inventory (permanently empty on sqlite-backed k3s, which
is most k3s installs), Rancher `settings` and k3s `Addons` (tables you read once
— a row in the Resources pane is not free), and every VictoriaMetrics feature
that needed an HTTP endpoint. A lens pack talks to the Kubernetes API and
nothing else; a sparkline cell that needs a reachable VM endpoint would break
that and render blank on most rows besides.

## Also

- A new test runs the **real** shipped packs through the registry and fails if
  any pack is dropped. A cross-pack short-alias collision parses fine and then
  vanishes into `LensErr` — exactly the failure that is invisible until someone
  asks where their kinds went.
- `just test-perf` was matching `TestRowCount` and therefore skipping
  `TestLensRowCount`. The lens perf guard was dead under the perf gate; it runs
  now.
- `docs/lenses.md` documents the filter form
  `.status.conditions[?(@.type=="Ready")].status`, which already worked and is
  what every pack here needs, plus the escaped-dot form for label keys
  (`.metadata.labels.fleet\.cattle\.io/repo-name`) — unescaped, k8s jsonpath
  splits on the dots and the column is empty on every row forever.
