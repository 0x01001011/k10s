**Three more operators, a graph you can read as a tree, one new key, and
frames that cost 85% less.** cert-manager answers "which certificate dies
first", Flux reconciles without the `flux` binary, Gateway API says which
listener a route failed to attach to, `X` draws the ArgoCD and Kargo graph
three hops deep instead of one, `ctrl+y` writes the current view to a file with
its credentials stripped, and every graded cell now carries a mark as well as a
colour.

## cert-manager — the EXPIRES column

`cert-manager.io/v1`: Certificates, CertificateRequests, Issuers,
ClusterIssuers. Today there is no answer to "which cert expires first" short of
a shell loop — `kubectl get certificates -A` gives you READY and AGE, and the
expiry lives in `.status.notAfter`, one `-o jsonpath` per certificate.

That column needed one new Go formatter, `format: until`, and the reason is
worth stating: `format: age` renders `ShortHumanDuration(time.Since(t))`, which
for a *future* instant is negative, and apimachinery prints anything below -1s
as the literal `<invalid>`. The best column in the backlog would have read
`<invalid>` on 100% of **healthy** certificates. Past instants fall back to an
age with a leading `-`, because `3d` and `3d` do not distinguish "expires in
three days" from "expired three days ago".

Two severity tables, not one: a Certificate that is not Ready grades **error**,
a CertificateRequest that is not Ready grades **warn**. Ready=False is the
normal in-flight state of a pending request, and error-grading it would float
healthy requests above genuinely broken certificates in the worst-first sort.

No renew button: `cmctl renew` appends an Issuing condition to
`.status.conditions`, and a merge patch of a conditions *list* would clobber
Ready. There is no declarative write to wrap, so there is no action.

## Flux — reconcile, suspend, resume, without the CLI

Kustomizations, GitRepositories, HelmRepositories, HelmReleases. Reconcile
writes `reconcile.fluxcd.io/requestedAt` and the pane spins until
`.status.lastHandledReconcileAt` echoes the token back — a real value match,
because a single-key annotate is the case where the ack can be exact. Force and
reset on HelmReleases write two annotations sharing one token, which is what
`ShouldHandleForceRequest` requires, and they ship **without** an ack: the ack
for a multi-key annotate degrades to a presence check, which would report
success before the controller had done anything.

**OCIRepositories are deliberately absent, and the reason is the gate.**
`OCIRepository` reached `source.toolkit.fluxcd.io/v1` only in Flux v2.6. On a
2.4/2.5 cluster `requires` would still pass — that group/version is served, by
GitRepository and HelmRepository — and the resource check would then find no
`ocirepositories` and drop **the whole pack**. Four working kinds would vanish
with no message, indistinguishable from "Flux is not installed". One kind is
not worth hiding the other four on every cluster one version behind.

HelmRepositories carry no reconcile for a related reason: since v2.2 an
OCI-type HelmRepository is never reconciled at all, so the annotation would be
written and then acked against a field no controller will ever set — a spinner
running the full 45-second timeout on an object that was never going to answer.

## Gateway API

GatewayClasses, Gateways, HTTPRoutes, GRPCRoutes. `ATTACHED` is
`.status.listeners[*].attachedRoutes`, space-joined — `1 0` means the second
listener has nothing attached. It is paired with `LISTENERS`, not with `PORTS`,
because `GatewayStatus.Listeners` is a `+listType=map` keyed by name with no
ordering guarantee against `.spec`; reading status tokens positionally against
spec tokens is an assumption upstream never makes.

The route condition columns are **not graded**, unlike the Gateway ones. A
route with two `parentRefs` — one Gateway per listener, or internal plus
external, the standard pattern — renders `True False`, which matches no entry
in a severity table and falls through to *unknown*. Unknown outranks ok, so a
healthy two-parent route would be marked "?" and sorted above every healthy
single-parent one. A severity table matches whole cell values, and a
space-joined cell is not a value.

## `X` — the GitOps graph as a tree ([#7](https://github.com/0x01001011/k10s/pull/7))

`R` answers "what is next to this": one hop, flat. That is the wrong shape for
the two tools whose whole model is a graph — a Kargo pipeline is a DAG, an
ArgoCD AppProject a fan-out — so reading either one hop at a time means holding
the structure in your head while you navigate.

`X` walks the same declared edges three hops and draws them, each object's own
graded cells on its line:

```
kargo-stages/dev   + Healthy  ! Running
├─ kargo-stages/staging   x Unhealthy  x Failed   via field
│  └─ kargo-stages/prod   + Healthy  + Succeeded   via field
└─ kargo-warehouses   (not loaded — open this kind to resolve)
```

The walk is generic, so every pack gets it. Four edges were added for the two
that motivated it: `stages -> stages` via
`.spec.requestedFreight[*].sources.stages[*]` — the self-edge that *is* the
promotion DAG, giving fan-in and fan-out from one field — `stages ->
warehouses` so a pipeline tree has a root instead of starting halfway down,
`applications -> appprojects` via `.spec.project`, and `applications ->
applicationsets` via ownerRef for generated apps.

Every bound has a reason: depth 3 (the fourth hop is mostly pods, which the
table lists better), 120 objects and **reported** when hit (a tree that quietly
stops is indistinguishable from a small cluster), three graded cells per line
(more wraps, and a wrapped tree loses the indentation that makes it a tree).
One visited set for the whole walk, not one per branch — the stage-to-stage
edge resolves both ways, and a per-branch set would bounce between dev and
staging until the depth counter ran out.

Nothing starts a watch, and the walk runs in a `tea.Cmd`, off the render path:
`test-perf` and `test-race` are unchanged by it.

## 85% faster frames, 93% less garbage ([#4](https://github.com/0x01001011/k10s/pull/4))

The render hot path had no benchmark — only the store did — so the first commit
of that work was `BenchmarkView` and `BenchmarkKeypressFrame` at 140x44 against
the mock backend, which is what makes the rest of these numbers comparable
across commits.

`lipgloss.Style.Render` re-resolves both hex colours and re-formats the ANSI
sequence on every call, and the table row loop built a fresh style per cell
across ~40 rows x ~8 columns: profiling put it at 43% of one frame, half of
that in colour resolution alone. Escape pairs are now rendered once per
fg/bg/bold combination and reused. The pair comes from lipgloss' own output, so
frames stay byte-identical — verified with `cmd/shot` before and after, which
is the point of having a headless renderer.

Two correctness fixes fell out of the same work:

- Wide runes broke column alignment. A cell measured by rune count rather than
  display width — `"日本語テスト"` is 16 cells in a 10-cell column — and
  `tableBody` passed the width it *computed* rather than the width it measured.
  Reachable with ordinary input: pod names, event messages, lens JSONPath
  columns are all arbitrary cluster data.
- Two zone-scanner limits are now recorded in the code rather than left as
  invariants the next change could break silently: zone ids are never pruned
  (safe only because every id comes from a bounded set), and the suggestions
  popup is drawn outside the `modalOpen` guard, so it does slice the zones it
  covers.

## Severity you can read without colour

Every graded cell now leads with a mark — `+` ok, `!` warn, `x` error, `?`
unknown — on both grading paths, the lens one and the builtin `statusColors`
one. Half-glyphed tables would be worse than none, so it was that or nothing.

The width is reserved up front rather than added per cell, so the column no
longer jitters as a status changes; the cost is two cells of value width in one
column per table. Verified against real frames at 80, 100 and 140 columns
across eleven builtin kinds: same column set at every width, no overflow.

## ctrl+y — export the current view

One key writes the selected object's YAML, its describe output and the visible
table to a file, and toasts the absolute path. No clipboard: a clipboard
library would be a new Go module, it shells out to binaries absent on headless
boxes, and OSC 52 truncates below a realistic payload. A path is what you paste
into a ticket anyway.

**Redaction is the feature, not a detail.** Secret `data` and `stringData` are
blanked wherever they appear — including a Secret nested in a List — along with
`last-applied-configuration`, which embeds a whole object and would otherwise
smuggle back out what was redacted above it.

Two leaks found in review and closed before merge:

- Credential keys are matched **normalised**. kubectl's generic describer — the
  one every CR and every lens-pack kind goes through — renders field names
  through `smartLabelFor`, which camelCase-splits them, so a CR's
  `clientSecret` prints as `Client Secret:`. Matching raw spellings leaked
  exactly the objects the lens packs exist to show, in a file whose YAML
  section had redacted the same value correctly.
- A credential passed as a **container flag** (`--client-secret=…`) has no key
  to match on: in YAML it is a bare string in an `args` list, in describe output
  a line with no `key: value` shape at all. Exporters, grafana and OIDC proxies
  all take credentials this way.

References stay readable — `secretName`, `secretRef`, `secretKeyRef` name a
Secret rather than containing one, and losing them makes an export useless for
the debugging it exists for.

The toast shortens from the **middle**: the tail of a path is its filename, the
one part you have to retype, and a tail-truncated path names no file at all.

## Smaller

- `ctrl+y` is in `cmd/shot`'s key table, so the one new binding can be replayed
  headlessly. A key that cannot be put in a frame cannot be verified the way
  this repo verifies UI changes.
- While a toast is showing, the status hints give up width to it. The hints are
  the same every frame; a toast may be the only place a result exists.
