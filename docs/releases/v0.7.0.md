**A table that fits the terminal it is in, and says what it does not know.**
Pods open grouped under their owner, any column sorts, and the columns that
survive a narrow screen are the ones worth keeping rather than the ones that
happened to be declared first. `t` opens the owner tree. Meters gained a shape
channel, a sparkline and a chart — and stopped drawing an empty bar for a node
at 6%. Two keys that cannot be undone are no longer one `enter` away.

## The 80×24 terminal ([#14](https://github.com/0x01001011/k10s/pull/14))

Chrome took 8 of 24 rows and 38 of 80 columns before a single pod was drawn,
and the banner was assembled at full length and then cut by the block — so the
first row ended on `nodes` with no count after it, the gauge row ended
`42%    81` with a memory total cut inside the number, and the `ns ▾` and
`theme ⟳` buttons sat off screen **with their click zones still marked**.

The banner is now 4, 2 or 1 rows by width, gauges shrink 16 → 10 → 6 and drop
their absolute figures, and the Actions pane collapses below 96 columns while
the sidebar stays — its keys are also on the status bar and in the palette,
whereas the sidebar is the only thing saying where you are. Each header
segment carries a priority and is **dropped whole, never cut**; a zone is
marked if and only if its label is on screen.

Columns changed the same way. The shrink loop used to take cells from the
widest column, which is always NAME, so at 100 columns NAME was already
`api-gateway-7d9f4…` while four columns were still displayed — two pods
differing only in their hash suffix rendered identically. Dropping took the
rightmost column, which is a fact about declaration order and not about
importance: AGE died at every width while NODE and CPU outlived it. Both are
policy now, and widths are measured in display cells rather than bytes, so a
single event message in Japanese no longer pushes real columns off the edge.

An 80×24 terminal goes from 12 visible pods to 17, with full names and full
statuses.

## Rows under their owner

Opening Pods gives you the shape you already hold in your head:

```
▾ api-gateway · rs 7d9f4c8b6d                             2
▌  1 api-gateway-7d9f4c8b6d-2xk4p   1/1  + Running   142m
   2 api-gateway-7d9f4c8b6d-hv8qz   1/1  + Running   128m
▾ cache-redis                                             2
```

This is one level of collapsible headers over a row slice that stays flat,
globally ordered and flatly indexed. Row numbers stay continuous and count
objects, so folding a group does not renumber the rows below it; selection
stays an index into the same slice, so every action is untouched; headers are
never selectable. `space` folds, `:group` changes the key, and a search
ignores folding entirely — the sidebar's rule, because a match hidden behind a
fold makes the filter look broken.

Knowing the owner costs nothing: `ownerReferences` is already on the pod, so
grouping starts no watch. The Deployment name is recovered from the
ReplicaSet's pod-template-hash rather than looked up, and where a name does
not have that shape — a StatefulSet member, a bare pod — the owner name is
printed as-is. A Deployment name is never guessed.

## The owner tree (`t`)

Grouping is one level. `t` opens the other thing: a real Deployment →
ReplicaSet → Pod tree where every node is an object.

```
▌deploy/api-gateway  2/2
 └─ rs/api-gateway-7d9f4c8b6d  2
    ├─ po/api-gateway-7d9f4c8b6d-2xk4p  + Running
    └─ po/api-gateway-7d9f4c8b6d-hv8qz  + Running
 deploy/billing-worker  ! 0/1
 └─ rs/billing-worker-6f8d9c5b7  0
    └─ po/billing-worker-6f8d9c5b7-qq91x  x CrashLoopBackOff
```

Actions follow the node under the cursor — `d` on a Deployment describes the
Deployment, `l` on a pod reads its logs — and the Actions pane lists what that
node can do. It is opt-in and deliberately second: most of what people want
from "show me the tree" is answered by grouping, and the part that is not is
the part that costs. A tree needs the ReplicaSet and Deployment *objects*,
which means informers that opening Pods deliberately does not start. `t`
starts them, on the keypress, and says so. Opening Pods still watches exactly
one kind.

A filter keeps the ancestors of every match, dimmed and unselectable. That
fork — an ancestor on screen is either a lie about what matched or its absence
is a lie about the shape — is the cost of a tree, and is why the flat list
stays the default.

## Sorting

Click a header to cycle ascending, descending, default; `<` and `>` walk the
sort column, `S` flips direction. Cells are parsed rather than compared as
text, because `10m` < `2h` is false as a string and so is `2Gi` > `900Mi`.

The type is decided per *column*, not per cell. A single value is often
ambiguous — `10m` is ten minutes in AGE and ten milliCPU in CPU, and nothing
in the string says which — so each value offers the set of kinds it could be
and the column is the intersection: the `2h` beside it settles the `10m`.

Cells with no value sort last in both directions. A descending CPU sort whose
top ten rows are unmetricked pods has answered a different question than the
one that was asked.

## Honest columns

A bare `-` meant five different things — unknown, unset, defaulted, not
applicable, and pending — and all five were dimmed, so a cell still waiting on
something read exactly like one that had settled. It is replaced by `<none>`,
`<cluster>`, `n/a`, `pending` and `lost`, and only the one that is actually
waiting is graded.

Some of those were wrong rather than vague. An HPA showed `-` for a minimum
the API defaults to `1`. A Deployment showed one image under a header reading
`IMAGE`, singular and unqualified, when it had three containers. CPU and MEM
showed `-` whether the metrics API had never answered or simply had no reading
for that pod yet — so a cluster with no metrics-server was indistinguishable
from a pod using no CPU.

## Meters, sparklines and a chart

The cluster gauge computed `pct * width / 100` and truncated, so at width 16
**every reading from 1% to 6% drew an empty bar** — a node at 6% was
pixel-identical to a node at 0%. A negative reading panicked. Bars are drawn
in eighths now, which fixes both and keeps 99% and 100% apart.

Severity was also carried by colour alone, and red against green is the worst
possible pair for deuteranopia. Every bar leads with a grade mark (`·` `!`
`×`) and the trough carries ticks at the 60% and 85% thresholds, so "how close
to warn" is readable without knowing the palette.

```
 CPU  ·██████···┊···┊··  38%    18.4/48 cores
```

`:spark` adds an inline CPU sparkline; `:chart` plots the same window as a
braille chart under the table — 2×4 dots per cell, so a 60×8 panel carries 120
points. Both read one 64-sample store, sampled on the repaint tick and never
from the render path: `View` runs per keystroke and only over visible rows, so
a series fed from there would append duplicates while you typed, nothing while
you idled, and miss every row scrolled past.

`K10S_ASCII=1`, or a locale that has not said it speaks UTF-8, switches every
glyph to an ASCII ladder — chosen once at startup, because a frame that mixes
the two sets is worse than a plain one.

## Writes that ask first

`D` opened a confirm that `enter` alone could fire, and `enter` is also the
universal "open" key — so deletion sat one keystroke from every table. `u`
drain, which evicts every pod off a node, was gated the same way. Both now
require the object's name to be typed. The mechanism already existed and lens
packs already used it; the core actions had simply never adopted it.

`e` applied whatever was on disk when the editor exited. Quitting `vi` with
`:q`, or an editor that crashed and left the file untouched, wrote the object
back to the cluster. The bytes handed to `$EDITOR` are now compared on the way
out: unchanged means nothing is applied, and an empty file is refused.

Every verb is findable. The palette searched kinds and objects but never
actions, which is how `R`, `X` and `ctrl+y` came to appear in no pane, no hint
string and no search — reachable only by already knowing the key.

## Under it

`tableData()` is the single read path for the table and had no memo, so one
frame called it three to five times, each a full formatted row build — 488µs
and 8018 allocations at 2000 pods. Now once.

The perf guards did not measure what they claimed. `TestKeypressLatency` drove
`j` and `k`; `j` is unbound and `k` opens the command prompt, so from the
second iteration every keystroke was typed into a text field that grew to some
four hundred characters, and the frame under measurement was a zoomed prompt.
Both guards drive the arrow keys now, and the test asserts focus never left
the table.

A frame at 140×44 costs 0.60ms and 423 KB, against a stated budget of 1ms and
512 KiB. Grouping and sort are most of the increase from 0.45ms, and are the
number to watch.
