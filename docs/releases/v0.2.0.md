**Your operators are in the sidebar now.** ArgoCD, Kargo, CNPG, Longhorn and
Traefik get real tables — sync and health, promotion phase, cluster phase,
volume robustness — with the daily verbs on the keys next to them. None of
it is five features. It is one mechanism plus five YAML files, and it costs
*fewer* API calls than the CRD view it replaces.

## Lenses ([#1](https://github.com/0x01001011/k10s/pull/1))

A **lens** is a declarative pack: which custom resources an operator owns,
what belongs in a row, and which actions apply. Built-in lenses are embedded
in the binary; your own go in `~/.k10s/lenses/*.yaml`.

```yaml
name: argocd
requires: [argoproj.io/v1alpha1]   # invisible unless this is served
kinds:
  - key: argocd-apps
    gvr: argoproj.io/v1alpha1/applications
    columns:
      - {header: SYNC,   path: .status.sync.status,   severity: sync}
      - {header: HEALTH, path: .status.health.status, severity: health}
```

**Nothing appears on a cluster that does not run it.** The gate is one
`ServerGroups()` call plus a resource check — the group/version alone is not
enough, because Argo Workflows, Rollouts and Events all serve
`argoproj.io/v1alpha1` without ever installing the Application CRD.

### Worst rows first

A column naming a `severity` table drives both its colour and the sort. The
rule is **worst across every severity column, skipping empty cells**:

- A `Synced` app that is `Degraded` is not healthy. Taking the first column
  would call it healthy, because ArgoCD declares SYNC before HEALTH.
- An empty `OPERATION` cell is not a status. Grading absence would float
  every idle Application to the top.

`unknown` is drawn subtle, not red: "the operator has not said" is not a
failure.

### Verbs on the digits

| Key | What |
|-----|------|
| `1`–`9` | the selected kind's lens verbs — sync, refresh, promote, fence, detach, back up now |
| `R` | relationships: one hop out, both directions |

An action you cannot run right now stays **listed, with its reason** —
pressing it says the reason out loud. A button that vanishes is a mystery,
and one that fires against the wrong object is worse.

Two gates. `confirm: "true"` is the ordinary modal; **typed** confirmation
asks for the object's own name and is used for writes no controller can
undo — fencing a Postgres primary, rolling an Application back. Both end
with the equivalent `kubectl` line, so you can check what the button claims
to do before agreeing to it, and reproduce it in a runbook afterwards.

Waiting is visible. Kargo echoes a refresh token into
`.status.lastHandledRefresh`; the pane spins until it matches what was
written. A timeout reads `sent, no acknowledgement yet` — not "failed",
because the write did go through, and saying otherwise sends you to retry a
request that is already queued.

### Relationships

`R` walks one hop, in both directions: from a pod up to the CNPG Cluster
that owns it, across to its latest Backup, down to the PVC, across to the
Longhorn Volume backing it. A neighbour whose kind has never been opened is
listed and marked **not loaded** — a different answer from "does not exist",
and only one of them is fixed by opening that kind.

## Two disclosures the UI makes, not just the docs

**ArgoCD sync bypasses ArgoCD's own RBAC.** `argocd-rbac-cm` is enforced by
`argocd-server`. Writing `.operation` directly on an Application is a plain
Kubernetes update the Argo policy engine never sees — effectively "sync
anything" for anyone holding `update` on `applications`. The sync modal says
so. If you need Argo policy enforced, deny `update` on `applications` and
use the Argo CLI.

**Kargo promote needs a virtual verb.** The webhook issues a
SubjectAccessReview for `promote` on `stages`; plain `create` on
`promotions` is not enough, and the refusal arrives as a webhook message at
create time rather than a 403 on the thing you clicked. That message is
shown verbatim, because it names the permission you are missing.

## Smaller fixes

- A service port cell like `80/TCP` is no longer coloured as a failing
  ready-ratio. The heuristic now requires both halves to be numbers.
- The cursor follows its **object** across a re-sort. Severity order changes
  whenever any row's status does, so a positional cursor would quietly move
  onto a different object between one keystroke and the next.
- A broken lens pack now says so. Previously a typo'd YAML file simply never
  appeared, which looked exactly like "those CRDs are not installed here" —
  a normal, intended, silent outcome.

## Trying it without a cluster

```bash
k10s demo        # then :ctx → k10s-demo-prod
```

The demo carries one headline kind per tool on that context, gated the way
discovery gates the real thing, with columns and verbs read from the shipped
packs — so what you see offline is what the binary does against a real
cluster.
